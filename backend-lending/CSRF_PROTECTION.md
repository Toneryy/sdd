# CSRF Protection

## Важно: Для REST API с JWT токенами CSRF защита обычно НЕ нужна

CSRF атаки работают только с автоматически отправляемыми браузером куками. 
Поскольку JWT токены отправляются в заголовке `Authorization` (а не в куках), 
они **не уязвимы** к CSRF атакам.

## Когда CSRF защита может быть полезна

1. Если вы используете куки для хранения токенов (не рекомендуется для REST API)
2. Если у вас есть формы, которые отправляются напрямую (без JavaScript)
3. Для дополнительной защиты "на всякий случай"

## Как включить CSRF защиту

1. Установите переменную окружения:
   ```bash
   ENABLE_CSRF_PROTECTION=true
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Обновите frontend для отправки CSRF токена в заголовках (см. ниже)

## Как работает CSRF защита

1. При GET запросе сервер устанавливает CSRF токен в куку с флагами:
   - `HttpOnly: true` - недоступен из JavaScript (защита от XSS)
   - `Secure: true` (в production) - только через HTTPS
   - `SameSite: strict` - защита от CSRF

2. Сервер также отправляет токен в заголовке ответа `X-CSRF-Token`

3. Frontend должен отправлять этот токен в заголовке `X-CSRF-Token` при каждом изменяющем запросе (POST, PUT, PATCH, DELETE)

4. Сервер проверяет совпадение токена из куки и заголовка

## Обновление Frontend

Если CSRF защита включена, нужно обновить `frontend-lending/src/services/api.ts`:

```typescript
// После получения ответа от сервера, сохраняем CSRF токен
const csrfToken = res.headers.get('X-CSRF-Token');
if (csrfToken) {
  // Сохраняем в памяти или state
  localStorage.setItem('csrf_token', csrfToken);
}

// При каждом запросе добавляем заголовок
if (csrfToken) {
  headers.set('X-CSRF-Token', csrfToken);
}
```

## Токен в DevTools

Если вы видите CSRF токен в DevTools (Application > Cookies), это нормально.
Важно, что он имеет флаг `HttpOnly`, что означает:
- ✅ Токен **недоступен** из JavaScript (`document.cookie` не покажет его)
- ✅ Защита от XSS атак
- ✅ Токен отправляется автоматически браузером в куках

## Рекомендация

**Для вашего проекта (REST API с JWT в заголовках):**
- CSRF защита **не критична**
- Можно оставить `ENABLE_CSRF_PROTECTION=false` (по умолчанию)
- Основная защита уже есть через JWT токены в заголовках

Если токен, который вы видите в DevTools, не используется в коде - это может быть токен от другого сервиса или прокси. Его можно игнорировать.
